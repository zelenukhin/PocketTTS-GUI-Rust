# CUDA_FEASIBILITY — CUDA FP32 для Shtorm ONNX (Windows, RTX 3060)

## Обновление 2026-11-08 (этап проверки достоверности)

### TF32: дефолт провайдера ВКЛЮЧЁН — исправлено

Тройная проба (`ep_probe`, `out/ep_traces`): одинаковые входы, три настройки
CUDA EP на двух графах:

| Граф | unset vs tf32=0 | unset vs tf32=1 | tf32=0 vs tf32=1 |
|---|---|---|---|
| flow_lm_flow (Gemm) | побитово равны | побитово равны | побитово равны |
| mimi_encoder (Conv) | **отличаются** (1.2e-4) | **побитово равны** | отличаются |

Вывод: **дефолт ONNX Runtime CUDA EP = `use_tf32=1`** для свёрточных путей
(cuDNN). То есть CUDA-замеры `bench_run1` на свёртках (mimi_encoder/decoder)
шли с TF32 — подозрение из задачи подтвердилось. Gemm-пути (flow_lm_main/flow)
TF32 в этой сборке не меняет вовсе.

Исправление: `session_builder` теперь **всегда передаёт `use_tf32=0` явно**
(`Device::Cuda{allow_tf32:false}` по умолчанию; `cuda_tf32()` — только для
диагностики). Строгий FP32 гарантирован на всех графах. bench_run2 — с фиксом.

### Фактическое распределение операторов (Chrome-trace профилирование)

Полная генерация одной фразы с `with_profiling` (события узлов по сессиям):

| Сессия | Всего узлов | CUDA | CPU | Что на CPU |
|---|---|---|---|---|
| flow_lm_main | 55 845 | 39 639 (71%) | 16 206 | только shape/служебные: Unsqueezex3504, Gatherx3504, Concatx2628, Castx1752, Slicex438, Reshapex438, … |
| flow_lm_flow | 11 830 | 11 830 (**100%**) | 0 | — |
| text_conditioner | 1 | 1 (100%) | 0 | — |
| mimi_encoder | 362 | 247 (68%) | 115 | shape-операции |
| mimi_decoder | 2 110 | 1 660 (79%) | 450 | shape-операции |

Все вычислительно тяжёлые узлы (Gemm/MatMul/Conv) исполняются на
**CUDAExecutionProvider**; на CPU остаются только операции формы/индексации,
которые CUDA EP не размещает — это нормальная и близкая к оптимальной картина
для данного EP. Молчаливого «всё упало на CPU» нет (проверено трассировкой,
а не фактом регистрации провайдера).

### Вердикт (без изменений после проверок)

CUDA FP32 работает; наивное включение даёт ~1.2–1.7x к CPU. Причина —
покадровый цикл: на каждый 80-мс кадр одна сессия `flow_lm_main` с 18
стейт-тензорами KV-кэша (~75 МБ суммарно), копируемыми CPU↔GPU каждый шаг.
IoBinding не делался (по правилам этапа — после базовых измерений).

## Как подключено

- Крейт `ort =2.0.0-rc.11`, фича `cuda`, `load-dynamic`.
- GPU-сборка onnxruntime 1.23.2 (PyPI-колесо), `ORT_DYLIB_PATH` → onnxruntime.dll.
- Провайдеры: `[CUDA{device_id, use_tf32=0}, CPU]` — CPU как узловой fallback.
- **Признак реальных GPU-вычислений** — дельта `nvidia-smi --query-gpu=memory.used`
  (WDDM не отдаёт per-process) + трассировка (см. выше). Smoke предупреждает,
  если CUDA выбран, а VRAM не выросла.

## Портативность CUDA-рантайма (проверено)

Запуск с PATH = только `C:\Windows\{System32,}` + локальный `deps\portable\`
(без venv/torch/системного CUDA) — CUDA работает (VRAM +2153 МБ, генерация ОК).
Минимальный пакет — 15 DLL (2.3 ГБ, «жирные» torch-сборки; перечень в
PREPARATION_REPORT §10). Попытка убрать `cufft64_11`/`cudnn_adv64_9`/`cudnn_cnn64_9`
ломает регистрацию CUDA EP → **молчаливый CPU-fallback** (пойман нашим
VRAM-контролем — кейс задокументирован, DLL обязательны).

## Возможные оптимизации (план, НЕ делать до решения по измерениям)

- **I/O Binding / резидентные GPU-буферы стейтов** (`ort::io_binding`): убирает
  перенос ~75 МБ стейтов на каждый кадр. Ожидание: RTF CUDA заметно ниже 0.4.
- Гибрид main+flow=CUDA / decoder,encoder=CPU (уже поддержано архитектурой).
- CUDA Graphs для статических форм.

## Риски

- WDDM: per-process VRAM в nvidia-smi недоступна (дельта totals — рабочий признак).
- Память: ~2.1 ГБ VRAM на CUDA-инстанс (арена); 3 инстанса GUI ≈ 6.4 ГБ из 12.
- CPU-fallback молчалив на уровне узлов: обязательна VRAM-проверка в смоуках
  (реализована) и полнота DLL-пакета (проверено).

## Минимальный план, если CUDA понадобится быстрее CPU

1. IoBinding для стейтов main-сессии.
2. Замер bench до/после (та же фраза, 100 чанков).
3. Если RTF < 0.35 не достигнут — гибрид и повторный замер.
4. Отчёт в BENCHMARKS.md; выбор «CPU vs CUDA по умолчанию» — по цифрам.
