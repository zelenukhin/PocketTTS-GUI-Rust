Этапы G1/G2/G2.1/G3/G3.1/G4/G4.1/G5/G5.1/G5.2 завершены. Следующий
крупный — CUDA-P2B, только по отдельному заданию. Документ разделён на
ФАКТИЧЕСКОЕ состояние (что реализовано и проверено) и ИСТОРИЧЕСКИЙ
первоначальный план (как задумывалось до G1; местами не реализовано
буквально — расхождения перечислены явно).

## G5.2 — финальная проверка GUI (2026-11-10)

  egui смещены относительно рендера — ограничение автоматизации.

## Фактическое состояние (G1–G5.1)

### Что есть

- Одиночный файл и безопасный пакетный режим (.txt/.md/.log, рекурсивно,
  без symlink), прогресс «файл K/N» + чанки, изоляция ошибок, отмена.
- Модель Fast/Slow/Custom (FP32-only, INT8 не загружается), CPU/CUDA
  (RTX), CUDA — I/O Binding main-графа по умолчанию; смена устройства —
  перезапуск приложения (ORT грузится в процесс один раз).
- Параметры генерации: температура, шаги декодирования, EOS (порог −6…1,
  хвосты ≤4/≥5 слов None/0–10; дефолты −4/5/3 teratts-android; кнопка
  «Значения teratts-android»), seed (−1 — случайный), анти-повторы,
  денойз (без модели — статус Missing), яркость.
- Паузы (масштаб, пауза абзаца, макс. токенов), воркеры (авто CPU 2 /
  CUDA 1 или вручную), потоков ORT.
- Вывод: WAV / MP3 / Opus с раздельными пресетами (несовместимый пресет —
  ошибка, не тихой подстановкой), ffmpeg с автопоиском, папка результата,
  лог чанков.
- Перезапись (G5/G5.1): чекбокс «Перезаписывать существующие файлы»
  (дефолт выкл. — существующий результат пропускается); при включённой —
  атомарная замена только после успешного синтеза, старый файл сохраняется
  при ошибке/отмене; сообщения различают «создан новый файл» /
  «ФАЙЛ ОБНОВЛЁН (старый заменён)» / «Пропущено» / «ОТМЕНЕНО … старый
  файл сохранён» / «ОШИБКА ПУБЛИКАЦИИ».
- Отмена и фазы (G5.1): Generating → Finalizing → Publishing →
  Completed/Cancelled/Failed; единая точка решения о публикации — отмена
  до неё не публикует ничего, после неё «Стоп» отключён и статус
  показывает «Сохранение результата…» (между файлами пакета «Стоп»
  возвращается).
- Безопасность путей результата: физические проверки (reparse-точки,
  принадлежность каталогу результата, совпадение с текстом/голосом/
  моделью) ДО создания каталогов; создание без следования по ссылкам;
  повторная валидация после создания.
- Журнал с копированием/очисткой (очистка не трогает файлы на диске),
  тёмная тема, подсказки ошибок ort::init по устройству.
- Настройки: собственный `PocketTTS-GUI-Rust.json` рядом с exe (G6.5; прежде `shtorm_gui_settings.json` — миграция при старте)
  (round-trip неизвестных ключей, атомарная запись tmp+MoveFileExW,
  миграция устаревших `"auto"` EOS → −4.0). Импорта Python-настроек НЕТ.
- Портативная сборка (exe-relative модели/ORT/ffmpeg/VC++ runtime;
  `--portable-check/selftest*`).

### Архитектура фактическая

- `crates/gui`: `settings.rs`, `app.rs` (форма/фазы/Стоп), `job.rs`
  (`execute_job`/`execute_batch` — напрямую `app_core`, не subprocess),
  `batch.rs` (DFS без walkdir), `resources.rs` (резолвер), `main.rs`.
- События задания: `JobEvent { Progress, Phase, FileProgress, FileDone,
  Log, Finished(JobResult) }` через mpsc + `ctx.request_repaint()`.
- Отмена = `Arc<AtomicBool>`; закрытие окна при живом задании — CancelClose
  + отмена + автозакрытие; сиротских ffmpeg нет (Drop присоединяет).
- Синтез — `app_core::pipeline::synthesize_stream` (тот же путь, что CLI),
  поэтому WAV GUI == CLI побитово при одинаковых настройках.

### Проверено

CPU/CUDA × WAV/MP3/Opus, отмена/повтор, перезапись (существующий/новый/
отмена/ошибка ffmpeg), пакетная перезапись, паритет GUI==CLI
(374444 байта), портативные комплекты. Итоги и команды — `HANDOFF.md`.

## Исторический первоначальный план (до G1; НЕ актуален буквально)

Первоначально планировался функциональный порт Python
`pocket-tts_gui.py` «как есть». Ключевые расхождения с реализацией:

- **Общий конфиг с Python** (`settings_pocket_tts.json`, маппинг всех
  ключей Python, голосовые пресеты `male_deep`/`female_silky` и
  `.safetensors`) — НЕ реализовано: с G1 у GUI собственный конфиг, с G5
  импорт Python-настроек удалён; голос — только WAV-референс.
- **«Авто»-значения EOS из runtime.json, «Кадров после EOS»
  (Авто/None/0–3), пересчёт 5→6/3→4** — НЕ реализовано: с G4.1 параметры
  EOS задаются явно (−4/5/3 по teratts-android), EOS из runtime.json не
  читается вовсе (программная семантика teratts-android; задокументировано
  в `docs/BENCHMARKS.md`).
- **Устройство Auto/CPU/CUDA** — НЕ реализовано: явный выбор CPU/CUDA,
  скрытых fallback нет; смена в одной сессии требует перезапуска.
- **«Перезапуск воркеров каждые N файлов»** — НЕ реализовано: пул
  создаётся/освобождается на файл; фиктивный переключатель не добавлялся
  (оценка — `docs/G3_BATCH.md`).
- **Шаги декодирования 1–32** — фактически 1–8.
- Экранный layout (свёртки «Источник и голос / Модель и устройство /
  Параметры генерации / Паузы и воркеры / Вывод / Журнал», диалоги
  «Обзор…», прогресс-бары) — реализован и сохранён.
